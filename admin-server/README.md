# Адмін-сервер ROCK HATA

Локальний бекенд для адмін-панелі (`panel.html`). Живе на
ноутбуці бару в Docker, нічого не платиться за хостинг. Публічний сайт
(`rockhatabar.github.io`) від цього сервера не залежить — він і далі читає
звичайний статичний `menu-data.js`; цей сервер лише переписує той файл і
пушить його в репозиторій після кожної правки в панелі.

## Що всередині

- **Postgres** — меню, акаунти персоналу, журнал правок.
- **backend** (Node/Express) — авторизація (JWT), API для панелі, і
  публікація: після кожного збереження генерує новий `menu-data.js` +
  бампає версію кешу в `index.html`, комітить і пушить у `main`.
- **cloudflared** (опційно) — якщо треба заходити в панель не тільки з
  вайфаю бару, а й з дому, поки ноутбук/Docker увімкнені.

## Перший запуск

1. Встанови [Docker Desktop](https://www.docker.com/products/docker-desktop/)
   на ноутбук бару.
2. У GitHub: **Settings → Developer settings → Personal access tokens →
   Fine-grained tokens** — створи токен, обмежений тільки цим репозиторієм,
   право **Contents: Read and write**.
3. Скопіюй `.env.example` у `.env` в цій папці й заповни:
   - `JWT_SECRET` — будь-який довгий рядок (`openssl rand -hex 32`)
   - `PGPASSWORD` — будь-який пароль для локальної бази
   - `GITHUB_TOKEN` — токен із кроку 2
4. Підніми базу й бекенд:
   ```
   docker compose up -d --build
   ```
5. Створи перший акаунт (власниці) — власне ім'я і роль `owner`:
   ```
   docker compose exec backend npm run create-staff -- oksana "Оксана" owner
   ```
   Команда виведе логін і **пароль одноразово** — збережи його, повторно
   він ніде не показується (зберігається тільки хеш).
6. (Один раз) якщо в базі ще нема меню — імпортуй поточний `menu-data.js`
   із репозиторію:
   ```
   docker compose exec backend node src/import-existing.js /repo/menu-data.js
   ```
   Якщо `/repo` ще порожній (перший запуск), спочатку зроби будь-яку
   правку в панелі — вона сама склонує репозиторій; або підклади файл
   вручну.
7. Відкрий `panel.html` (з самого сайту або локально),
   при першому вході панель запитає адресу сервера — вкажи
   `http://localhost:3000`, якщо відкриваєш з того ж ноутбука.

## Віддалений доступ (не обов'язково)

Якщо власниця хоче правити ціни з дому, поки бар відкритий:

1. У [Cloudflare Zero Trust](https://one.dash.cloudflare.com/) →
   **Networks → Tunnels** → створи тунель, вкажи публічний хостнейм →
   `http://backend:3000`.
2. Скопіюй токен тунелю в `.env` як `CLOUDFLARE_TUNNEL_TOKEN`.
3. Запусти з профілем tunnel:
   ```
   docker compose --profile tunnel up -d
   ```
4. В панелі як адресу сервера вкажи публічний хостнейм із кроку 1
   замість `localhost`.

Тунель живий, тільки поки ввімкнені ноутбук і Docker — рівно як і
задумано (закрився бар → сервер і доступ ззовні зникають, публічний сайт
на GitHub Pages як працював, так і працює).

## Ролі персоналу

- **owner** (власниця) — усе, що і бармен, плюс керування акаунтами
  персоналу (розділ «Персонал»).
- **bartender** — повний доступ до меню: назва, опис, фото, ціна,
  додавання й видалення товарів. Не бачить розділ «Персонал».

Під кожним товаром панель показує, хто востаннє його редагував і коли —
незалежно від ролі.

Створити ще один акаунт можна або тим самим `create-staff`, або з-під
власниці прямо в панелі (кнопка «Персонал»).

## Бекапи

`db-data` — Docker volume з базою. Мінімум раз на тиждень:
```
docker compose exec db pg_dump -U rockhata rockhata > backup-$(date +%F).sql
```
